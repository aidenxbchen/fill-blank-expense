# 填空报销：采购工作台设计

依据：[Anthropic 官方 frontend-design](https://raw.githubusercontent.com/anthropics/skills/main/skills/frontend-design/SKILL.md)，2026-11-09 全文阅读。

## 构建前的判断

这是一张员工要完成、可以中断续填的采购工作单。主角应该是项目与可核对的发票，而不是营销标题或巨大金额。原页面的居中宣传句、多个等权按钮、连续同形圆角面板，削弱了操作顺序；手机上把桌面表格缩小也不能解决编辑问题。

初案“居中标题 + 三张功能卡”与通用 SaaS 模板过近，已舍弃。采用一张工作台：桌面上项目在左，文件入口在右，票据明细横跨全宽；手机按实际顺序纵向展开，同一组表格控件变为逐票带标签的编辑单。预算选项和发票行的边界都有业务含义，其余区域不用卡片堆叠。经典入口、保存、新建收进更多菜单，记录与设置仍直接可达。

## Tokens

六个核心颜色：纸面 `#FFFFFF`、工作区 `#EDF1F7`、深蓝墨 `#182D49`、次要文字 `#586B82`、动作蓝 `#245AC7`、错误红 `#AD3745`。浅底、边界、焦点环由动作蓝和墨色的低透明度派生。完成使用动作蓝与明确文字，不依赖颜色辨别状态。白底按钮文字和所有正文保持可读对比。

中文优先字体：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`，适合中文采购字段，避免加载远端字体和额外追踪；金额使用 `"Avenir Next", "PingFang SC", sans-serif` 与等宽数字。字号阶梯 12 / 13 / 15 / 17 / 22 / 28px，正文行高 1.65，标题 1.3。小字只用于辅助信息；手机输入保持 16px，触控区域至少 44px。主要标题左对齐，说明文字限宽约 40 个汉字。

间距 4 / 8 / 12 / 16 / 24 / 32 / 48px；控件圆角 8px，工作面 16px，状态和选项的小圆角 6px。阴影只给浮层和悬浮操作。主工作区最大 1240px，桌面边距 32px、手机 16px。

## 布局与识别点

```
桌面
品牌                     我的报销 / AI 设置 / 更多   登录
保存状态（失败时重试）
上传发票 —— 补充信息 —— 核对草稿 —— 发起采购
准备这次采购的发票
┌ 项目 / 已通过预算 ┐ ┌ 原件上传入口                 ┐
└──────────────────┘ └────────────────────────────┘
识别汇总：可编辑台账（日期、商户、票号、金额、类别、状态）
                                           确认，补充信息

手机
品牌 / 登录
我的报销 / AI 设置 / 更多
保存状态 + 实际步骤
项目 → 上传 → 逐票编辑 → 下一步
```

唯一的视觉识别点是“折角票据”品牌标记与同源文件图形；它指向票据整理的真实工作。其余元素克制、对齐、无装饰渐变，无自动入场动画。问答保留项目名与历史常用推荐，选择后立即显示选中并锁住重复动作。

## 反馈与可访问性

- 文件状态来自实际生命周期：排队、上传原件、识别、待核对 / 已识别 / 失败。只有真实完成数量，无模拟百分比。长请求用不定旋转指示，禁用重复操作。
- 自动保存明确显示待保存、保存中、已保存、失败；失败给重试入口，版本冲突继续使用原有记录恢复规则，绝不覆盖。保存不移动焦点。
- 对话框设置焦点、圈定 Tab、Escape 关闭并返回触发入口；浮层期间背景 inert，恢复原状态。全局 toast 与局部状态使用 aria-live。键盘焦点可见，输入有名称；尊重 reduced-motion。
- 收据成功只展示真实结果，失败保留草稿并显示下一步；测试只用隔离的合成数据，不发起真实审批或消息。

## 完成后的自检

- 对照规范复查：保留一个折角票据图形，无大数字首屏、紫色渐变或自动入场；项目选择与上传构成工作面。移除旧默认页样式累积，classic 使用其自有样式不受影响。顶部设置和记录直接可达，保存 / 新建 / 经典入口置于「更多」，原有 HTML IDs 无移除。
- 浏览器在完全拦截网络的合成示例中核验 1200px / 390px：页面宽度与视口一致、无非表格溢出；手机金额输入 16px，导航触控至少 44px。实际设备软键盘、中文字体渲染和视觉细节仍需人工验收。
- 浏览器交互通过：保存失败 → 本机草稿保留 → 重试已保存；对话框焦点、Tab 循环、Escape 返回触发入口、背景 inert；项目问题与历史常用选项、立即选中 / 禁用、回答推进；记录空状态；模拟提交失败保留原件及草稿、双击只发出一次模拟请求；模拟原件上传 → 识别 → 成功。识别期间编辑另一票，完成后新识别值和用户修改均保留。
- 测试：95 项 Python unittest、发票抽取脚本、7 种采购问答及建议排序检查、JS 语法、`web/test-ui.cjs`（重复点击、失败恢复、禁用状态保留、DOM hooks）。测试脚本可生成完全离线示例：`node web/test-ui.cjs --fixture > /tmp/baoxiao-ui.html`，打开该 HTML 不会连接业务 API。该 fixture 只包含合成数据，任何未注册请求都被阻断。
- 截图：Browser 截图两次超时（桌面与 390px），均未生成图片，无可交付截图路径；不把 DOM 布局检查当作截图或最终视觉验收。
- API、SQLite schema、权限、OAuth 发起身份、采购字段映射、原件校验和版本守卫没有修改。未创建生产审批、未发送真实消息，未读取密钥或真实发票内容。
