# 六环节报销流程（2026-11-25）

上传发票 → 问问题 → 匹配预算 → 匹配关联审批 → 预览 → 提交。

问答只收集用途、采购方式、项目和适用的银行档案；不再在问答里混选预算或出差申请。预算选择移出上传页，放在独立环节。预算为空时须说明原因，可以继续。

`matchedBudget`、`noBudgetReason`、`relatedApproval` 分开保存，`workflowVersion=2` 标识新协议。差旅缺出差申请会在关联环节和服务端同时阻止继续；非差旅可以选择无额外关联。兼容字段 `selectedBudget` 只供旧提交与差旅校验协议消费，不再作为唯一预算存储。旧草稿按原候选类型恢复至对应字段，不改原发票或原件。

预览包含可编辑发票清单以及最终只读核验，两者都处于第五环节。可返回修改预算和关联。成功回执后显示第六环节完成。新草稿阶段 budget / relation 纳入服务端持久化校验。

服务端分别核验预算归属与关联审批可见性、状态、定义限制。预算和额外审批都存在时，向飞书 connect 提交去重后的两个实例编号。无预算说明同时保存在本地草稿、最终快照，并带入飞书采购事由。原件、OAuth 发起人、防重复与审批后学习准入保持不变。

上游限制：当前采购表单的关联审批控件在多数方式下为必填。如果既无预算又无额外审批，新流程允许填原因并进入预览，但预览会明确提示飞书表单限制，不能伪造编号或绕过必填。若实时定义改为选填，服务端已支持不提交空 connect。预付款方式隐藏 connect 时，预算仅作为本地支出上下文保留。

验证：204 项后端回归；新增 7 项流程规则覆盖独立预算 / 关联、无预算说明、差旅必填、上游必填与选填、伪造预算拒绝；1440 / 390 宽度用 25 张合成发票走六环节、预填、冲突修正与一次模拟提交。没有创建真实审批。

## 预览核验状态修复（2026-11-26）

当前草稿只读核验实测 8.28 秒返回 HTTP 200。旧前端将全量 claim 做结果关联键，期间后台匹配改写自动 travel 事实，造成核验成功但结果因上下文不同被静默丢弃，按钮仍禁用且页面停在核验中。

预览期间不允许后台匹配改写发票事实或自动关联；核验结果按会话、用户、内容及请求代次归属，旧请求不能覆盖新结果。同内容在途核验去重。内容有变化时显示重新核验，不静默返回。

核验进度移至提交按钮，显示“正在核验表单与 X 份原件…”及 aria-busy。成功后才授权当前内容提交；本地冲突直接显示需处理原因；超时、服务端错误、内容变化显示可点击重试状态，点击只进行只读核验，不提交审批。错误与通过详情在按钮附近显示。预览核验使用独立 60 秒超时预算。

测试覆盖核验成功、超时重试、内容变化、重复调用、旧失败晚到、后台匹配不修改预览，以及 1440 / 390 宽度下按钮加载状态与 25 张合成发票完整流程。没有创建真实审批。
